## 📜 Smart Contracts

### MockStablecoin.sol
**Purpose**: Demo USD stablecoin for testing  
**Key Functions**:
- `faucet()` - Get free test tokens (1000 mUSDC per hour)
- `approve(spender, amount)` - Approve TokenSale spending
- `balanceOf(account)` - Check balance

**Example Usage**:
```javascript
const stablecoin = await getMockStablecoinContract(signer);
await stablecoin.faucet(); // Get 1000 mUSDC
await stablecoin.approve(tokenSaleAddress, amount);
```

### RealEstateToken.sol  
**Purpose**: ERC-20 tokens representing property ownership  
**Key Functions**:
- `getOwnershipPercentage(account)` - Get ownership %
- `getOwnedValue(account)` - Get USD value owned
- `getPropertyInfo()` - Get property metadata

**Example Usage**:
```javascript
const propertyToken = await getRealEstateTokenContract();
const ownership = await propertyToken.getOwnershipPercentage(userAddress);
const value = await propertyToken.getOwnedValue(userAddress);
```

### TokenSale.sol
**Purpose**: Sell property tokens for stablecoins  
**Key Functions**:
- `buyTokens(amount)` - Purchase property tokens
- `calculateCost(amount)` - Calculate mUSDC cost  
- `getSaleStats()` - Get sale statistics

**Example Usage**:
```javascript
// Complete buy flow
const tokenSale = await getTokenSaleContract(signer);
const cost = await tokenSale.calculateCost(ethers.parseUnits("100", 18));
await stablecoin.approve(tokenSaleAddress, cost);
await tokenSale.buyTokens(ethers.parseUnits("100", 18));
```

### IncomeDistributor.sol
**Purpose**: Distribute rental income to token holders  
**Key Functions**:
- `getClaimableAmount(user)` - Check claimable dividends
- `claimDividend(round)` - Claim from specific round
- `claimMultipleDividends(rounds[])` - Bulk claim

## 🔒 Security & Limitations

### Security Measures Implemented
✅ **OpenZeppelin Contracts**: Battle-tested, audited contract templates  
✅ **ReentrancyGuard**: Protection against reentrancy attacks  
✅ **Access Control**: Role-based permissions (owner, minters)  
✅ **Input Validation**: Comprehensive parameter checking  
✅ **Safe Math**: Automatic overflow/underflow protection  
✅ **Transfer Restrictions**: Compliance-ready whitelisting  

### Known Limitations (Hackathon Context)
⚠️ **Legal Structure**: Mock legal framework - production requires SPVs  
⚠️ **KYC/AML**: Basic whitelisting - production needs full identity verification  
⚠️ **Property Custody**: Simulated - real custodial arrangements needed  
⚠️ **Price Oracle**: Fixed pricing - production needs dynamic valuation  
⚠️ **Insurance**: Not implemented - property insurance integration required  

### Production Considerations
🔮 **Oracles**: Chainlink for property valuations and rental rates  
🔮 **Legal**: Licensed SPV structures in investor jurisdictions  
🔮 **Compliance**: Full KYC/AML integration with certified providers  
🔮 **Multi-sig**: DAO governance for property decisions  
🔮 **Insurance**: On-chain parametric insurance for property risks  

### Attack Vectors & Mitigations

| Attack Vector | Risk Level | Mitigation |
|---------------|------------|------------|
| **Reentrancy** | Low | OpenZeppelin ReentrancyGuard |
| **Integer Overflow** | Low | Solidity 0.8.x automatic checks |
| **Access Control** | Medium | Role-based permissions, multi-sig |
| **Front-running** | Medium | Commit-reveal schemes for sensitive ops |
| **Flash Loan** | Low | No external price dependencies |
| **Governance Attack** | High | Time delays, multi-sig requirements |
